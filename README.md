# FLOW 운영 관리

한국어 제품·고객·출고·A/S 관리 웹앱입니다. GitHub Pages + Supabase 무료 플랜으로 로그인과 공유 PostgreSQL DB를 연결할 수 있습니다.

## 실행

저장소 루트에서 `python3 -m http.server 8000 --bind 127.0.0.1` 실행 후 index.html을 엽니다. npm 설치나 빌드는 필요하지 않습니다.

## 클라우드 설정

[Supabase 연결 안내](supabase/SETUP.md)에 따라 새 프로젝트에서 [DB 설치 SQL](supabase/schema.sql)을 실행하고 직원 계정을 `아이디@flow.invalid` 형태로 생성·확인하고 권한을 등록한 뒤 config.js에 공개 URL과 publishable key를 입력하세요. 관리자용 비밀 키는 클라이언트에 넣지 않습니다. 설정이 없으면 연결 안내와 기존 브라우저 데이터 보기 버튼이 표시됩니다. 프로젝트 연결 전에는 실제 로그인/DB 공유가 동작하지 않습니다.

## 기능

- 제품·고객·출고·A/S 등록·수정·검색·CSV 내보내기
- 아이디·비밀번호 로그인(내부 Auth 이메일 변환), 관리자만 삭제 가능, 초대된 직원만 데이터 접근
- 중복 시리얼번호/고객코드/출고 방지, 관련 이력 삭제 제한
- 출고 이력이 있으면 제품 상태를 출고로 표시하고 출고 삭제 시 기존 상태로 복귀
- A/S 완료일 입력 시 완료 표시, 완료일/접수일 검증
- DB 트랜잭션과 버전 검사를 통한 동시 수정 충돌 방지
- 공유 데이터는 새로고침 버튼으로 갱신, 자동 실시간 동기화는 미구현
- 자체 가입·비밀번호 변경·재설정 화면은 미구현, 관리자가 계정 관리

기존 localStorage 데이터는 클라우드로 자동 이전되지 않습니다. CSV는 내보내기용이며 가져오기 기능은 없습니다.

## 개발 검증

테스트 도구만 설치하려면 `npm ci`를 실행합니다. `npm test`는 PGlite의 PostgreSQL 엔진에서 실제 스키마·권한·제약조건을 검사합니다. 정적 서버를 8001 포트에서 실행한 뒤 `npm run test:browser`로 브라우저 검증을 실행합니다. Chromium 경로는 기본 `/usr/bin/chromium`이며 `CHROMIUM_PATH`로 바꿀 수 있습니다. 다른 서버 주소는 `TEST_BASE_URL`로 지정합니다.

브라우저 테스트는 실제 SQL 엔진에 연결되지만 Auth/API 전송은 로컬 테스트 대역을 사용합니다. 실제 Supabase 로그인·네트워크·배포 검증을 대신하지 않습니다. 설정 파일도 테스트 대역으로 교체하므로 실제 프로젝트에 테스트 데이터를 쓰지 않습니다.

## 자동 시리얼번호

제품 등록 시 제품 구분과 생산일을 선택하면 DB가 시리얼번호를 생성합니다. `SN + 제품 구분(0/1/2) + YYMMDD + 구분별 누적 순번`이며 순번은 최소 4자리, 9999 다음은 10000입니다. 날짜 변경이나 제품 삭제로 순번을 초기화하지 않습니다. 기존 DB에는 [최신 변경용 SQL](supabase/migrations/20261020_lot_model_only.sql)을 먼저 실행해야 합니다. 기존 시리얼번호는 유지됩니다. 과거 생산량의 시작 순번 설정은 [설정 안내](supabase/SETUP.md)를 참조하세요.

등록 화면에서 ‘자동 생성’ 또는 ‘수기 입력’을 선택할 수 있습니다. 수기 입력은 입력한 번호를 저장하며 DB가 중복을 거부합니다. 자동 생성 형식의 수기 번호는 자동 순번에 반영됩니다. 이미 자동 생성 SQL을 설치했더라도 최신 수기 입력 변경용 SQL을 추가로 실행해야 합니다.

## 고객코드

고객 등록에서 자동 생성/수기 입력을 선택합니다. 자동 코드는 `C0001`부터 누적하며 9999를 넘으면 자릿수가 늘어납니다. 기존 코드와 관계는 유지되고, 자동 배정된 삭제 코드는 재사용하지 않습니다. 최신 [통합 업데이트 SQL](supabase/migrations/20261020_lot_model_only.sql)을 실행하면 기존 시리얼 기능과 고객코드 기능을 함께 적용할 수 있습니다. 적용 후 이전 SQL을 다시 실행하지 마세요.

## 수주관리

고객 주문을 한 수주에 여러 모델·사양·수량으로 등록합니다. 수주번호 자동 생성, 접수일·납기일·상태·비고, 품목 추가/수정과 취소, CSV 내보내기를 지원합니다. 출고에 수주 품목을 선택하면 모델·사양이 일치하는 재고 제품을 연결하며 주문·출고·남은 수량을 집계합니다. 수량 초과와 정보 불일치는 DB에서 거부합니다. 전체 수량 출고 시 완료로 표시하고, 출고 삭제 시 다시 계산합니다.

기존 DB에는 [최신 수주 통합 SQL](supabase/migrations/20261020_lot_model_only.sql)을 실행하세요. 기존 시리얼·고객코드·출고·A/S는 유지됩니다. 최신 SQL 적용 후 이전 SQL은 다시 실행하지 마세요.

## 수량 관리와 A/S 비용·입금

수주 품목에서 시리얼/수량 관리 방식을 선택합니다. 수량 품목은 시리얼 없이 출고 수량을 입력하고 수주 출고·남은 수량을 합산합니다. 기존 시리얼 출고는 수량 1을 유지합니다. 창고 재고 수량 관리는 포함하지 않습니다.

A/S 창에 유상/무상·청구금액·누적 입금액·최근 입금일을 기록하고 입금상태·미수금을 확인합니다. 은행 자동 연동이나 개별 입금 거래 장부는 아닙니다. 수리 완료와 입금 완료는 독립적으로 관리합니다.

기존 DB에는 [최신 통합 SQL](supabase/migrations/20261020_lot_model_only.sql)을 적용하세요. 이전 수량 관리 SQL을 따로 실행할 필요가 없고, 이전 SQL을 나중에 다시 실행하면 안 됩니다. 자세한 규칙은 SETUP.md를 참조하세요.

## 제조 LOT / A/S 시리얼 검색

제조 LOT 메뉴에서 생산 묶음을 등록하고 제품에 연결합니다. LOT별 연결 제품·출고 고객·A/S 이력을 조회하며 마감 LOT의 추가 연결 및 사용 중인 LOT 삭제를 차단합니다. 기존 제품은 LOT 미지정으로 유지됩니다. 최신 [LOT 통합 SQL](supabase/migrations/20261020_lot_model_only.sql)을 적용하세요. 이전 기능도 포함하므로 최신 파일 하나만 실행하면 됩니다.

A/S는 시리얼·모델·사양·고객명·LOT 번호로 검색해 제품을 선택합니다. 출고 제품 우선, 재고 제품 포함이며 결과는 최대 20개 표시합니다. 선택하면 모델명이 채워지고 검색어 변경 시 제품 선택을 다시 해야 합니다. 키보드 화살표·Enter로도 선택할 수 있습니다.

LOT 연결은 모델명만 검사하며 사양과 생산일이 달라도 연결 가능합니다. 마감 LOT 연결 제한과 사용 중인 LOT 삭제 제한은 유지합니다.
